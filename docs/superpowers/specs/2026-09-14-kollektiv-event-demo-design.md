# Kollektiv event demo — design

Date: 14 September 2026. Scope contract for a 2–3 hour build at a Claude Code build event.
Parent document: `docs/kollektiv-mvp/SPEC.md` (the MVP spec). Where this file is silent, the MVP spec wins. Where they conflict, this file wins for today only.

## Goal

A running SwiftUI app on the iPhone simulator that demonstrates Journey A (away for the weekend, cover request, volunteer accepts) and Journey C (volunteer to cook, who's eating) with a real Claude model call behind @House, using in-memory demo data. This is milestone M1 from the MVP spec plus a local-only slice of M3. It is not M2: there is no backend, no auth, no persistence.

## Decisions made today

| Question | Decision |
| --- | --- |
| Agent realism | Real Claude Messages API call from the app; tools execute against the local store |
| Repo | `ios/` inside this repo, not a new standalone repo |
| Time budget | 2–3 hours, so Week and Chores are read-only lists |
| Model provider | Anthropic Claude, replacing the MVP spec's OpenAI default. The provider adapter boundary stays |
| Project file | Generated by xcodegen from `ios/project.yml`; never hand-edit the pbxproj |
| Secrets | `ios/Secrets.xcconfig`, gitignored, supplies `ANTHROPIC_API_KEY` via Info.plist |
| Minimum iOS | 18.0 |
| Simulator | iPhone 17, iOS 26.5 |

## In scope

### Screens

- **House tab.** Butter background, `Our house.` heading, the bundled house illustration, three labelled door buttons (Meals, Chores, Plans), one status strip showing tonight's dinner count or the open decision, an **Ask the house** button that switches to Chat with `@House ` prefilled. Header holds a labelled **Demo person** switcher (Kristian, Sam, Mia).
- **Chat tab.** One channel. Human bubbles with initials, House messages with the agent avatar. Composer with a send button and an **@House** chip that inserts the mention at the cursor. The mention is stored as a token on the message, not detected by scanning body text. Task cards show state in words and a symbol. An open cover request shows **I can take it** to any member other than the initiator, and **Cancel request** to the initiator. Result messages name the exact date and person.
- **Week tab.** Read-only list for the next seven days, grouped by date, combining dinners, chore due dates and events. Rows are tappable into the dinner sheet where applicable.
- **Meals sheet.** Reached from the House door, the status strip, or a Week row. Shows date, dish, cook, time, and attendance split as Eating / Away / Not answered with names. Controls for the current demo person: Eating, Away, I'll cook (only when the slot is free).
- **Chores list.** Reached from the House door. Groups: Your turn, Coming up, Needs someone. The current demo person can mark their own occurrence done. No swap UI.

### Domain

One `@Observable` in-memory `HouseStore` seeded with a fixed week starting Monday 14 September 2026 in Europe/Oslo: three members, seven dinners, weekly kitchen and bathroom chores with dated occurrences, two events. It exposes the domain commands from MVP spec section 9 and nothing broader:

- `readHouseContext(range)`
- `setMyAttendance(actor, dates, status)`
- `volunteerToCook(actor, date, dish, time?)`
- `createCoverProposal(actor, occurrenceID)`
- `acceptCover(actor, proposalID, expectedRevision)` and `cancelCover(actor, proposalID)` — deterministic, not model-callable
- `completeChore(actor, occurrenceID)`
- `postMessage(...)`

Every command takes the actor from the app, never from tool arguments. Commands check membership, ownership and revision and return typed results or typed errors. The store is the single source of truth for every screen.

### Agent

An `@House` mention on send creates an `AgentTask` record (Working → Completed / WaitingForVolunteer / Failed) and starts one model run:

1. Build a system prompt containing the house name, timezone, today's date, member names, and the behaviour rules from MVP spec section 5 (own attendance only, own chores only, never claim success early, ask before ambiguous changes).
2. Send the task thread plus the tool definitions for the five section-9 tools. Set `max_tokens` conservatively and cap the loop at 6 tool calls.
3. Execute each tool call locally by mapping it to a store command with `actor = sender`. Return the store's result, including errors, as the tool result.
4. The model's final text becomes the House message. Any proposal created during the run is rendered as a card attached to that message.

`ClaudeAgentClient` is behind an `AgentClient` protocol. If no key is configured or the request fails, the task becomes Failed and the card shows **House couldn't finish this** with **Retry**. There is no scripted success path. Ordinary messages without the mention never start a run.

Clarification (`ask_task_question`) is accepted as a tool and rendered as a House question, but the follow-up reply does not resume the task today; the user re-tags @House. This is a stated cut.

### Assets and design tokens

Cobalt `#0755F5`, butter `#FFF08A`, coral `#FF765B`, teal `#28B99E`, cream `#FFFCF2`, navy `#07112F`. Rounded system font with heavy headings. The six PNGs from `docs/kollektiv-mvp/assets/icons-v1/` are copied into the asset catalog. Small tab-bar icons use SF Symbols.

### Tests

`KollektivTests` covers store commands against the acceptance matrix: A01 (only sender's dates change), A05 (claim free slot once), A06 (occupied slot preserved), A07 (assignment unchanged while pending), A08 (second acceptance fails with already-resolved), A15 (tool arguments cannot change the actor). The agent client is tested with a fake transport for the tool loop; live model behaviour is checked manually on the simulator.

## Out of scope today

Supabase, auth, invites, persistence across relaunch, Realtime, Journey B swaps, clarification resume, Household settings screen, event creation, dinner editing beyond attendance and cook, Dynamic Type audit, VoiceOver pass, dark mode, push, rate limiting and spend caps beyond the tool-call cap. All remain in the MVP spec as later milestones.

## Definition of done

- `xcodegen generate` then `xcodebuild` succeeds from a clean checkout with the example secrets file.
- On the iPhone 17 simulator: Kristian tags @House with the Journey A message, attendance changes for Fri–Sun only, a cover card appears, switching to Sam and tapping **I can take it** transfers the Saturday kitchen occurrence, Chores and Week reflect it.
- Journey C: "@House I'll cook vegetable curry on Thursday" records Kristian as cook; asking who's eating Thursday returns the recorded split.
- Unit tests pass.
- Screenshots of House, Chat and Week are captured for the demo.
